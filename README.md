# go-gostcrypto

[![CI](https://github.com/krotos139/go-gostcrypto/actions/workflows/ci.yml/badge.svg)](https://github.com/krotos139/go-gostcrypto/actions/workflows/ci.yml)
[![Примеры](https://github.com/krotos139/go-gostcrypto/actions/workflows/examples.yml/badge.svg)](https://github.com/krotos139/go-gostcrypto/actions/workflows/examples.yml)

Отечественные криптографические алгоритмы для Go: шифрование,
хэширование, электронная подпись и форматы, в которых всё это
встречается на практике — подписи `.p7s`, зашифрованные сообщения,
ключевые контейнеры `.pfx`.

Чистый Go, без ассемблера и без cgo. Внешних зависимостей нет — только
стандартная библиотека.

## Область применения

Библиотека **не является сертифицированным средством криптографической
защиты информации**. Она реализует алгоритмы по опубликованным
национальным стандартам, но оценку соответствия не проходила и на
сертификацию не подавалась.

Это учебная и исследовательская реализация общедоступных стандартов.
Коммерческого распространения нет: исходный код открыт под лицензией
MIT, готовые изделия не поставляются, услуги в области шифрования не
оказываются.

Для защиты информации ограниченного доступа она **не предназначена**.
Там, где по закону требуется сертифицированное СКЗИ — государственные
информационные системы, персональные данные, квалифицированная
электронная подпись, — нужно сертифицированное средство, и эта
библиотека его не заменяет.

## Что реализовано

Всё перечисленное реализовано полностью в указанном объёме и сверено с
контрольными примерами первоисточников.

| Стандарт | Что |
|---|---|
| ГОСТ Р 34.12-2015 | Блочные шифры «Магма» и «Кузнечик» |
| ГОСТ Р 34.13-2015 | Шесть режимов работы и три процедуры дополнения |
| ГОСТ Р 34.11-2012 | Хэш-функция «Стрибог», 256 и 512 бит |
| ГОСТ Р 34.10-2012 | Электронная подпись, девять наборов параметров |
| Р 50.1.113-2016 | HMAC, KDF, KDF_TREE, ВКО |
| Р 50.1.111-2016 | Парольная защита: PBKDF2, PBES2 |
| Р 50.1.112-2016 | Транспортный ключевой контейнер: PKCS#8 и PKCS#12 |
| Р 1323565.1.017-2018 | ACPKM, режимы с мастер-ключом, экспорт ключа KExp15 |
| Р 1323565.1.026-2019 | MGM — режим аутентифицированного шифрования |
| RFC 9215 | PKIX: сертификаты, запросы, списки отзыва, имена |
| RFC 5652, 4490, 4357 | CMS: подписанные и зашифрованные сообщения |
| RFC 3161, 5035 | Метка времени и ссылка на сертификат (CAdES) |
| ГОСТ 28147-89, 34.11-94 | Устаревшие алгоритмы для ранее выпущенных документов |

## Установка

```bash
go get github.com/krotos139/go-gostcrypto
```

Требуется Go 1.24 или новее.

## Пакеты

| Пакет | Назначение |
|---|---|
| `gost3412/kuznyechik`, `gost3412/magma` | Блочные шифры |
| `gost3413` | Режимы работы: ECB, CTR, OFB, CBC, CFB, имитовставка |
| `gost3411/streebog` | Хэш-функция «Стрибог» |
| `gost3410` | Выработка ключей, подпись, проверка |
| `mac`, `kdf`, `vko` | HMAC, выработка ключей, согласование ключей |
| `mgm` | Аутентифицированное шифрование |
| `acpkm` | Перевыработка ключа и режимы на её основе |
| `keywrap` | Экспорт ключа: KExp15 и устаревшие схемы |
| `gostasn1` | Сертификаты, запросы, списки отзыва, идентификаторы |
| `cms` | Подписанные и зашифрованные сообщения, метка времени |
| `pkcs8`, `pfx` | Кодирование ключа и ключевые контейнеры |
| `legacy/gost28147`, `legacy/gost341194` | Устаревшие алгоритмы |

## Примеры

Готовые к запуску программы — в каталоге [`examples`](examples), там же
их описание. Среди прочего есть `inspect-signature`: разбор чужой подписи
`.p7s` или `.sig` с проверкой.

```bash

```

## Устаревшие алгоритмы

Пакеты в `legacy/` нужны только для разбора ранее выпущенных документов:
в старом документообороте много подписей по ГОСТ Р 34.10-2001 с хэшем
ГОСТ Р 34.11-94, и без этих алгоритмов их не проверить. Для нового кода
они не предназначены — 28147-89 заменён «Магмой», 34.11-94 «Стрибогом».

| Пакет | Что | Первоисточник |
|---|---|---|
| `legacy/gost28147` | Блочный шифр, набор подстановок — параметр | RFC 5830, наборы из RFC 4357 |
| `legacy/gost28147` | Гаммирование, гамм. с обратной связью, имитовставка | RFC 5830, разделы 6-8 |
| `legacy/gost341194` | Хэш-функция, 256 бит | RFC 5831 |

Две особенности, на которых обычно ошибаются. Во-первых, у обоих
алгоритмов набор подстановок — параметр, а не часть алгоритма: на разных
наборах результаты разные. Во-вторых, ГОСТ 28147-89 и «Магма» — не одно
и то же: алгоритм тот же, но ключ и данные разбираются в обратном порядке
байт, поэтому на одном ключе они дают разный результат.

Рабочий пример: [`examples/legacy`](examples/legacy).

## Производительность

Измерено на Intel Core i7-9700K 3.6 ГГц, Go 1.24, amd64. Всюду медиана
пяти прогонов, пакеты идут по одному (`-p 1`): при параллельном запуске
замеры дерутся за ядра и занижаются в разы.

### Скорость операций

| Операция | Скорость |
|---|---|
| «Стрибог» 256, 8 КиБ | 58 МБ/с |
| «Стрибог» 512, 8 КиБ | 61 МБ/с |
| «Кузнечик», блок | 113 нс |
| «Магма», блок | 100 нс |
| «Кузнечик», гаммирование | 130 МБ/с |
| «Магма», гаммирование | 69 МБ/с |
| «Кузнечик», имитовставка | 128 МБ/с |
| MGM на «Кузнечике» | 53 МБ/с |
| CTR-ACPKM на «Кузнечике» | 94 МБ/с |
| Подпись, 256 бит | 168 мкс |
| Проверка, 256 бит | 596 мкс |
| Подпись, 512 бит | 930 мкс |
| Проверка, 512 бит | 3,42 мс |
| ВКО, 256 бит | 455 мкс |
| Подпись CMS | 0,70 мс |
| Проверка подписи CMS | 1,15 мс |
| Контейнер `.pfx`, сборка | 68 мс |
| Контейнер `.pfx`, чтение | 70 мс |

Блок здесь шифруется на месте, поэтому число — задержка одной операции:
следующий блок ждёт предыдущий. В режимах, где блоки независимы, тот же
«Кузнечик» выдаёт 78 нс на блок за счёт совмещения на конвейере.

Время работы с контейнером почти целиком уходит на PBKDF2: две тысячи
итераций HMAC на «Стрибоге» 512 — это так и задумано, парольная защита
должна быть медленной.

### Сравнение с другими реализациями на Go

Против [`pedroalbanese/gogost`](https://github.com/pedroalbanese/gogost)
и [`maxyotka/gost-crypto`](https://github.com/maxyotka/gost-crypto).
Все три замера в одном прогоне, на одних данных и на одной кривой;
результаты у всех трёх сверены и совпадают побайтно.

| Операция | go-gostcrypto | gogost | gost-crypto |
|---|---|---|---|
| «Стрибог» 256, 8 КиБ | **60 МБ/с** | 18 МБ/с | 23 МБ/с |
| «Стрибог» 512, 8 КиБ | **60 МБ/с** | 18 МБ/с | 23 МБ/с |
| «Кузнечик», блок | **78 нс** | 1406 нс | 855 нс |
| «Магма», блок | **99 нс** | 167 нс | 114 нс |
| Развёртывание ключа «Кузнечика» | 12,5 мкс | **5,6 мкс** | 414 мкс |
| Подпись, 256 бит | **169 мкс** | 1,72 мс | 2,30 мс |
| Проверка, 256 бит | **605 мкс** | 3,46 мс | 5,55 мс |
| Подпись, 512 бит | **924 мкс** | 6,65 мс | 8,83 мс |
| Проверка, 512 бит | **3,47 мс** | 13,70 мс | 18,32 мс |

Разрыв объясним: по «Кузнечику» здесь свёрнутые таблицы LS, по подписи —
своя арифметика Монтгомери вместо `math/big` и метод фиксированной
гребёнки. Единственная строка, где мы проигрываем, — развёртывание ключа,
и это плата за то же самое: ключи расшифрования заранее прогоняются через
обратное линейное преобразование, чтобы блок считался быстро. Для
долгоживущих ключей размен верный, для одноразовых — нет.

### Сравнение с КриптоПро CSP

| Операция | go-gostcrypto | КриптоПро CSP 5.0 |
|---|---|---|
| «Стрибог» 256 | 60 МБ/с | 174 МБ/с |
| «Стрибог» 512 | 60 МБ/с | 173 МБ/с |

КриптоПро использует рукописный ассемблер с AVX2; отставание переносимого
Go почти втрое — ожидаемое.

## Модель угроз

Формирование подписи выполняется за время, не зависящее от секретных
данных: своя арифметика поля с постоянным числом операций, полные формулы
сложения точек и выборка из таблиц под маской. Проверка подписи работает
только с открытыми данными.

Шифры и хэш-функции табличные, и адрес выборки зависит от обрабатываемых
данных — на машине, где противник может измерять время доступа к кэшу,
это остаётся источником утечки.
